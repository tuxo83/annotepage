Frequently asked questions

Everything you always wanted to know about annotepage, and a few things you would not have thought to ask.

See a detailed usage example→ See every way to install it→

What if I lose the key?

Key

In secure mode, the notes go with it. There is no recovery and no rotation — the key is what decrypts them, and the server has never had it. In open mode the key is written in the tag, on a page anybody can read, so it cannot be lost.

Can I let someone read the notes without writing any?

KeyWho can do what

No. The key reads and writes; there is no reader-only role.

What exactly is encrypted, and by what?

KeyPrivacy

The remark, its author, the element it points at and the page it is on — everything a reader wrote. Your browser encrypts it with AES-256-GCM, using a key derived from yours by HKDF-SHA-256, and sends the result. The key stays in the browser: it travels in the tag or in a paste, never in a request. What the server stores is a block of bytes it cannot open, a project id, and a blind index saying which page — which is how it can group notes without knowing a single path. The exact scheme is in FORMAT.md.

Where does the key come from?

KeySetting it up

Your browser draws it, on the install page, and sends it nowhere. The project id in the tag is derived from it and does not lead back to it — the server recognises that id, it never issues one.

What does the notes server see?

PrivacyYour own server

Counts, times, sizes, IP addresses and your domain. Never your paths, never your text — in secure mode it cannot read a line it stores.

Is there an account, a moderator, a way to delete a note?

Who can do whatPrivacy

None of them, and no notification either. A project is a key and the notes under it.

Can I switch from open to secure later?

KeyPrivacy

For new notes, yes: change the tag. The notes already written keep the mode they were written in, and nothing converts them.

Can the page sit behind a login?

PrivacyYour site

Yes. Neither the notes server nor the assistant ever opens it: the MCP talks to the notes API and to nothing else, and the page is opened by the reviewers’ own browsers, which are already signed in.

Can I try it on my own machine?

Setting it upYour site

Yes: localhost is a secure context, so the browser has the crypto it needs. But never declare localhost:3000 in a server’s list of domains — that name belongs to every machine on earth, so declaring it lets any of them write to your project.

Is it free?

Cost and licence

Yes, and it is MIT. The shared notes server at api.annotepage.com is free to use with nothing to install; running your own is free too, and that is the whole list.

Do I have to use your server?

Your own serverCost and licence

No. One PHP file installs your own, and the install page takes you through it. Whichever one you run, its address is what goes in the tag.

Can I run a version before everybody else?

Setting it upThe tag on your page

Yes, and it is one word in each place.

The tag on your pages — ask for @next instead of @2:

https://cdn.jsdelivr.net/npm/annotepage-client@next/dist/annotepage.js

Your own notes server — one line in internal/config-local.php, pointing it at the candidate branch:

'update_source' => 'https://raw.githubusercontent.com/tuxo83/annotepage/next/server/webroot/',

It stays hashed against the manifest either way: a candidate is checked exactly as a release is. Put main back and the next daily check returns it to the stable one.

The assistant — nothing. The MCP talks to your server whichever code it is running.

Why @2 and not @latest?

The tag on your pageNothing appears

Because it is not the ceiling it looks like. A page carrying @2 still ends up running version 3 — your notes server announces the client it works with, and the client fetches that exact version and replaces itself, major number included. What @2 decides is only which copy loads first.

And that order is the point. A major version is the one release allowed to change the protocol; the client is on a CDN and the server is on somebody's machine, so @latest would deliver the new client to every page the day it is published, in front of servers that have not moved yet. Announced instead, the server is already running it before it says so.

If you would rather have the newest whatever your server is running, ask for it — it is the same one word:

https://cdn.jsdelivr.net/npm/annotepage-client@latest/dist/annotepage.js

A release candidate never arrives through any of the three: ranges exclude pre-releases, latest is never moved to one, and the client refuses to install one on its own.

Where is the source?

Cost and licence

All of it, MIT: github.com/tuxo83/annotepage — the client, the notes server, the MCP and this site. The two published packages are annotepage-client (the tag) and annotepage-mcp (what plugs an assistant onto it). The server is not a package: it is one PHP file that fetches the rest.

Can I load it as a module?

The tag on your pageNothing appears

No, and it fails quietly. The client reads document.currentScript to find its own settings, and a type="module" script does not have one: nothing appears, and nothing is logged.

What if I pin the script with a wrong integrity digest?

The tag on your pageNothing appears

The browser refuses the file and the tool simply does not appear. Nothing on the page says why. The install page writes the digest for you when you ask for a pinned tag.

My site sets a Content-Security-Policy. What do I need?

The tag on your pageNothing appears

Two directives. script-src must allow wherever the client is served from, or it never loads; connect-src must allow your notes server, or fetch fails and the tool stands down in silence, as if nothing had been configured. style-src usually needs nothing: the stylesheet goes in as a constructed sheet, which is not an inline sheet in the policy’s sense.
