The server, in Node

The review server is a PHP app you install — or a Node package you drop into the app you already run. Same notes, the same browser client, the same format. No PHP, and no second server beside your own.

Run it on its own

From a terminal, nothing to write:

npx annotepage-server --project <your project id> --report-statistics false

It listens on :3000 and answers the client. --help lists the rest — --port, --db, --prefix, --relay, --config.

Embed it in your app

Or mount it where your app already answers requests:

import { createServer } from 'annotepage-server';
import { SqliteStore } from 'annotepage-server/stores/sqlite';
import { nodeListener } from 'annotepage-server/adapters';

const api = createServer({
    store: new SqliteStore({ file: './data/notes.sqlite' }),
    projects: { '<your project id>': { mode: 'encrypted' } },
    reportStatistics: false,
});
app.use('/annotepage/api', nodeListener(api));   // Express, http, Fastify…

The core is api.fetch(request) — a web-standard Request in, a Response out — so Express, Fastify, and the fetch runtimes (Bun, Deno, Cloudflare Workers) all take it as they are. The browser client points at the mount and is otherwise unchanged.

ⓘ The encryption does not move: the server stores ciphertext and never holds the key, exactly as the PHP one. A SQLite file written by either server is read by the other, so a project can move off PHP without touching a note.

The one choice with no default

Whether the server reports once a day — a random identifier, its version and three totals, and nothing else — is not decided for you: you pass report-statistics one way or the other. It is the only setting that sends anything off the machine.
