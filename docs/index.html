Someone reviewing a staging site clicks what they see — a heading, a button, a link — and writes what is wrong. An assistant reads the notes, fixes the code, replies saying what it measured, and resolves it with the version the fix ships in.

  • Free · MIT
  • Open source
  • Self-hostable
  • End-to-end encrypted · in the browser

Free, and not for sale. Run it on your own server; a shared one, open to everybody at no cost, comes next.

Put it on a page

If you can edit the page

Copy and paste a tag

One script tag at the end of <body>: no framework, no bundler, no build step, no dependencies.

Two steps, about a minute. Then a server has to answer, and there is no public relay yet.

01

Take the salt, and save it

Generated here, in your browser. This page makes no network request, so it has never existed anywhere else.

your salt — save this before anything else 
JavaScript is off — the client’s setup screen does the same.

Project id —, derived from that salt. It is public, and the salt cannot be worked back from it.

Salt lost = notes lost. No recovery, no escrow, no rotation. Put it where your team keeps its passwords, now — what that costs, in full.

02

Paste the tag it gives you

At the end of <body>, on the pages to annotate. The project id is filled in.

the finished tag 
<script src="https://annotepage.com/annotepage-client-2.0.1.js"
        integrity="sha384-VBUfe2CFvh85WRBCH1/uKse1O2wauw3at7B9gGC2fC8Y/sG03p9bZABq3MyUDbKE"
        crossorigin="anonymous"
        data-server="https://your-server.example.com/annotepage/api.php"
        data-project="7Qb1kZ3xNvA9dLpEqKf2Zt"
        data-version="1.4.13"
        defer></script>

The server is then told about the project in three lines of its configuration. The salt is not one of them: it never reaches the server, in any form.

How an assistant uses it

Collecting a remark is common; writing back into the thread, with a measurement and a version, is not.

plug it in 
npm install -g annotepage-mcp
claude mcp add annotepage -- annotepage-mcp

The remark arrives carrying the page, the element, the text on screen and the version being served, so a fix needs no conversation. Resolving states the version the fix ships in: until the site serves it, the note stays in front of the reviewer.
