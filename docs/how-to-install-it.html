Install the app on the server

  1. Upload one PHP file

    Anywhere under your web root. Open it: its button hashes the rest against the MANIFEST.

    It ends by printing your API address. Put it in the field at the top and the blocks below follow it. 

    https://raw.githubusercontent.com/tuxo83/annotepage/main/server/annotepage-install.php

  2. Answer its three questions

    It walks you through them, writes the configuration, and proves the browser cannot reach the notes before it finishes.

    Two of the three are the answers you gave above.

    annotepage — install

    annotepage

    The installer leaves this empty on purpose: the id does not exist while it runs. Your browser drew it above. 

    'projects' => array(
    '7Qb1kZ3xNvA9dLpEqKf2Zt' => array(
        'origins' => array('https://staging.example.com'),

    ),

  4. Keep it up to date

    One line in your crontab, once a day. The last screen gives it to you with the real path already in it. 

    17 4 * * * php <your install>/internal/update.php >/dev/null

  5. Keep it up to date

    One line in your crontab, or the same address pasted into your host’s scheduler. The installer writes the secret and shows it once. 

    17 4 * * * curl -fsS 'https://staging.example.com/notes/api.php?action=update&token=<the secret>'

  6. Change anything else by hand

    The installer wrote this file. Open it for what it did not ask about — a second origin, a relay, plain mode, credentials read from outside the web root.

    The second file in that folder is the commented template: every key, with what it costs written beside it.

PHP 7.4, with pdo_sqlite or pdo_mysql. For MySQL, have its host, name, user and password to hand. The rest is in INSTALL.md.

Install the tag on the site

  1. Paste the tag

    At the end of <body>.

    The key was drawn in this browser, just now, and sent nowhere.

    The id is derived from the key, in this browser, just now — the server recognises it, it never issues it. 

    <script src="https://cdn.jsdelivr.net/npm/annotepage-client@2/dist/annotepage.js"
                            data-server="https://api.annotepage.com/api.php"
                            data-key="<43 characters, drawn in your browser>"
                            defer></script>

    Where it goes, in what you use:

    No layout to edit: paste it before </body> in every page you want annotated, not only index.html. If your pages share a footer include, that is the one place to put it.

    Edit the layout your pages already use — src/layouts/*.astro — before </body>.

    Edit app/layout.tsx, inside <body> and last. On the pages router, pages/_document.tsx.

    No template to edit: declare it in nuxt.config.ts, under app.head.script, with body: true.

    Edit src/app.html, the shell every route is rendered into, before </body>.

    Edit the layout every view already renders into — app/views/layouts/application.html.erb — before </body>.

    Edit the base template your pages {% extends %}, before </body>.

    Edit resources/views/layouts/app.blade.php, the layout your views extend, before </body>.

    Edit templates/base.html.twig, the template every page extends, before </body>.

    Add it to your child theme’s footer.php, or hook it on wp_footer, which survives a theme update. There is also a plugin that writes the tag and nothing else.

  2. Hand the key over

    Each reviewer pastes it once.

    <43 characters, drawn in your browser>

Keep this key. Lose it and the notes go with it — no recovery, no rotation. Put it where your team keeps its passwords, now.

ⓘ Nothing appearing? A module, a wrong integrity digest and a Content-Security-Policy each stop it in silence — the three cases, answered.

Install the MCP on the assistant

  1. Install it

    One command to install it, one to plug it into your assistant.

    The key is on the page, so that is all there is. 

    npm install -g annotepage-mcp
claude mcp add annotepage -- annotepage-mcp

  2. Give it the key, once

    One file, on the machine where your assistant runs. Write it yourself, or hand it the key and let it write the file (less secure: the key crosses a provider’s logs).

    The address is on your tag. The key is the one your reviewers paste.

  4. Then ask it
